# Open-source release requirements

Recommended license decision: owner selects an OSI-approved license before code publication (Apache-2.0 is a candidate, not assumed). Include `LICENSE`, `NOTICE` where required, `CONTRIBUTING.md`, code of conduct, security policy, support policy and DCO/CLA decision.

Separate examples from real tenant identifiers. Use synthetic fixtures. Publish threat model, permission rationale, telemetry defaults, data inventory and vulnerability reporting channel. Release signed source tags and images with SBOM/provenance. Public issues must never receive customer logs containing tenant data or secrets.
